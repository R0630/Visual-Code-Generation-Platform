# App / User 接口测试指南（Knife4j）

## 一、密码是怎么存的

`UserServiceImpl.getEncryptPassword()` 的逻辑：

```java
final String SALT = "qiyiqi";
return DigestUtils.md5DigestAsHex((userPassword + SALT).getBytes(StandardCharsets.UTF_8));
```

即 **密文 = MD5(明文密码 + "qiyiqi")，32 位小写十六进制**。

等价 SQL：`SELECT MD5(CONCAT('明文密码','qiyiqi'));`

实测值：`user1234` → `0af56d7b5509b67739ed899d3eed8416`，`admin123` → `a16fa04b3f4fe95931e5e8902dde74e8`。
把这个哈希写进 `userPassword` 就能用对应明文登录。

### 关于 id

id 是 MyBatis-Flex **雪花算法**生成的 18 位值（时间戳 + 机器位 + 序列号），不是自增的，无法被遍历猜测。
上表 id 由项目自身的 `SnowFlakeIDKeyGenerator` 生成后固定写进脚本，因此每次重跑结果一致。

因为 18 位超过了 JS 安全整数范围（16 位），id 在接口里**全部按字符串传输**：
请求体要写成 `{"id":"471096585778905088"}`（带引号），query 参数直接填数字串，响应里 `id`/`userId` 也是字符串。

## 四、Knife4j 怎么用

1. 启动后端，访问 **http://localhost:8123/api/doc.html**（`context-path` 是 `/api`）
2. 左上角分组选 `default`
3. **必须先登录**：找到 `user-controller` → `POST /user/login`，请求体填：

   ```json
   { "userAccount": "user001", "userPassword": "user1234" }
   ```

   返回 `code=0` 即成功。登录态写在 `JSESSIONID` 里，Knife4j 与接口同源，后续请求会自动带 cookie。
4. 切换身份时重新调 `/user/login` 覆盖 session 即可（登录 admin001 才能调管理员接口）。
5. 接口按 `app-controller` / `user-controller` 分组，点「调试」→ 填参数 → 「发送」。
6. **id 现在统一是 18 位雪花值，且一律按字符串传输**：
   - query 参数框（`GET /app/get/vo?id=`）里直接填 `471096585778905088`，**不要加引号**；
   - 请求体 JSON 里**必须加引号**：`{"id":"471096585778905088"}`，不加引号会被当成数字而截断；
   - 响应里的 `id` / `userId` 也是字符串，复制出来可直接粘回请求体用。

### 关于查询参数的填写

分页接口的请求体里，**不用的字段可以留空字符串或 0，代码会自动归一化掉**（查询前会把空串转 null、
`id`/`userId`/`priority` 的 0 视为「不按该条件筛选」）。

之所以要这样处理：MyBatis-Flex 默认**只忽略 null，不忽略空字符串**。如果原样传入，会生成

```sql
WHERE cover = '' AND codeGenType = '' AND deployKey = '' AND id = 0
```

而库里这些字段是 `NULL`（`NULL = ''` 不成立），结果就是 `records` 恒为空。

另外两个容易踩的点：

- **精选接口不要传 `priority`**：精选本身已按 `priority >= 1` 过滤，再叠加 `priority = 0` 会互相矛盾、结果必空。
  现在代码已在该接口忽略传入的 priority，传了也不影响。
- **`sortField` 留空即可**：空字符串会生成非法的 `ORDER BY  ASC`。留空时走默认排序
  （我的应用 → 创建时间倒序；精选 → 优先级倒序 + 创建时间倒序）。
  若填写，只能是白名单内的字段，否则报 `40000`。

### 判断通过的标准

| 观察点 | 说明 |
|---|---|
| `code` | `0` 成功；`40000` 参数错误；`40100` 未登录；`40101` 无权限；`40400` 数据不存在；`50001` 操作失败 |
| `message` | 失败时要能对应上具体校验点，而不是笼统的「请求参数错误」 |
| `data` | 分页接口看 `records` 条数与 `totalRow` |

## 六、需要重点盯的几个点

1. **越权**（第 9、16、35、43、48、53 条）是本次最重要的用例，必须全部是 `40101` 或返回自己的数据。
2. **id 精度**：第 29 条用 19 位 id，若返回 `40400` 说明传参被前端截断，就是改 String 前的问题。
3. **null 覆盖**（第 12、45 条）：修复前会出现「改名把名字清空」「改名字把封面清掉」，修完应正常。
4. **pageSize=0 / pageNum=0** 未在上表列出，MyBatis-Flex 行为需实测，建议补一条观察是否 500 还是返回空列表。
